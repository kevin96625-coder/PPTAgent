## 1. 问题与目标

**动因(dogfood 实测)**:真实 12 页 SU7 deck 经 Gemini 给 8.2/全过,但渲染后**无法使用**——第 3 页是手绘通用轿跑(与 SU7 无关)、全 deck **零 `<image>`**、审查只看排版不看"配图对不对",造成虚假信心。

**第一手复核(2026-06-08,渲染 01/03/06/07)**:数据/Bento 页(06、07)其实**专业**;问题**高度集中在需要真实视觉资产的页**(封面/产品/设计页)。所以引擎不需要换,要补的是"真实图片 + 验证图片真的好"。

**结构性根因(已查代码)**:
- `agents/slide-core.md:97` 明令 "No external image references — all graphics must be inline SVG" → 管线被禁止用图,只能手绘 → 必然假图。
- 主 reviewer 把 `${SVG_CONTENT}` **文本**喂 Gemini(`skills/gemini-cli/SKILL.md:103`),**看不见**渲染后的照片 → 无法判断配图质量。

**目标**:让需要视觉资产的页**真正可用且专业**,并堵住审查盲区。**保留 Claude 手绘 Bento 引擎**(数据页已证明健康)。确定性机械自修(安全区/字号/对比度)拆到紧随的 **M2.6**。

**非目标(本里程碑不做)**:换 SVG 生成引擎(Gemini 出整页 SVG)、HTML 产物线、机械自修、PPTX 导出。

## 2. 关键决策(brainstorm 拍板)

| 决策点 | 结论 |
|---|---|
| M2.5 野心 | **聚焦修复**——保留 Bento 引擎,只攻图片+审查 |
| 图片来源 | **混合**:品牌实体(SU7/logo/真人)走真实图;抽象/场景/概念走 image-gen |
| 真实图获取 | **联网搜图下载嵌入**,在**资料调研阶段**进行 |
| 图源可靠性 | **人工预览门兜底 + 自动搜图减负**——脆弱的自动搜图**移出**"好不好"的关键路径;品牌图最终靠人工门 + 用户官方图保证 |
| 审查盲区 | **双保险**:自动 reviewer 加"资产/贴切/专业度"视觉维度 + 早期人工预览门 |
| 机械自修 | **拆出为 M2.6**,紧随 M2.5 |

## 3. 架构与数据流

```
outline(每页标 asset 字段)
 → research(brand-entity 尽力搜候选图 / scene 走 image-gen → images/ + images-manifest.json)
 → draft
 → slide-core 出【样片】(封面 + 1 张资产页:嵌 <image> + 图主导版式 + 配图处理)
 → 🚦 人工预览门(样片 PNG + 全部资产页候选图 PNG + 缺图清单;用户接受/替换/丢官方图)
 → slide-core 批量出【其余页】(沿用确认的风格;缺图页标 needs_real_image,不画假物)
 → review-core(资产页:SVG→PNG 渲染 → Gemini 视觉评图含"资产贴切/专业度"维;数据页:维持文本审查)
 → 交付(images/ 拷进 output/)
```

> 关键时序:**样片在预览门之前、批量在预览门之后**——这才真正避免 dogfood 的"1h53m 全量白跑"。

**单元边界**(各块职责单一、接口清晰、可独立测试):
1. outline `asset` 字段(content 层,数据契约)
2. research 搜图/取图(尽力而为,非关键路径)
3. slide-core 图能力(版式 + 嵌入 + 缺图 flag)
4. SVG→PNG 渲染工具(共享小工具)
5. review-core 视觉审查(消费渲染工具)
6. 人工预览门(workflow 编排)

## 4. 组件设计

### 4.1 outline `asset` 字段(content 层)
- `outline.json` 每页新增:
  ```json
  "asset": {
    "needed": true,
    "kind": "brand-entity",        // brand-entity | scene | none
    "query": "小米 SU7 侧面 官方图 高清",
    "caption": "SU7 低风阻轿跑姿态"
  }
  ```
- `outline-architect.md` 增加判定规范:封面/产品/设计页 → `brand-entity`;场景/概念/情绪页 → `scene`;纯数据/对比/引言页 → `none`。
- `planning-validator.js` 增加 `asset` 结构校验(枚举、`needed=true` 时 `query` 必填),硬错阻塞、软警提示。

### 4.2 research 搜图/取图(research-core,尽力而为)
- 读 outline 中 `asset.needed=true` 的页:
  - `kind="brand-entity"` → **尽力**联网搜图下载(见 4.2.1)。
  - `kind="scene"` → 调 `skills/image-gen`(`--out <run_dir>/images/...` + image-manifest)。
- 统一落 `run_dir/images/slide-NN-*.{jpg,png}` + 写 `images-manifest.json`(页号、kind、本地路径、来源 URL/backend、宽高、状态 fetched|generated|missing)。
- **拿不到不阻塞**:写 `status:"missing"`,交给人工预览门处理。

#### 4.2.1 自动搜图能力(net-new,非关键路径)
- agent-reach **当前不能搜图**(纯文本/字幕)。新增一个**尽力而为**的图片搜索+下载脚本:
  - 探测可用图源(优先已注册 MCP 如 exa;否则 curl 抓图搜结果页;全缺 → 跳过)。
  - 基本质量过滤:最小分辨率门槛、跳过明显缩略图。
  - **降级即静默标 missing**,绝不阻塞、绝不伪造。
- ⚠️ 明确定位:这是"初稿减负",**不在"好不好"的关键路径上**。质量保证靠 4.6 人工门。

### 4.3 slide-core 图能力(slide-core)
- **改 `slide-core.md:97`**:资产页**允许** `<image>`;数据页仍纯矢量。删除"绝对禁止外链图片"。
- **图主导版式配方**(新增到 svg/版式参考):full-bleed hero(整图+渐变蒙版+标题压图)、图文分栏(image inset + 文本列)、inset-with-scrim(卡片内嵌图+暗角保文字)。
- **配图处理约束**:按目标宽高比裁剪/`preserveAspectRatio`;暗底优先无背景/透明 PNG,否则全出血+渐变 scrim 保证文字 ≥ 对比阈值;全 deck 图风格一致性提示。
- **嵌入方式**:生成/审查期用**相对路径引用**(`href="images/slide-NN.jpg"`)保持 SVG 文本短(避免 base64 撑爆 Gemini token);交付期把 `images/` 拷进 `output/`(对齐 P5 workflow-san `addImage` 文件式路径)。
- **缺图防线**:`asset.needed=true` 且无可用图 → 在 SVG 留占位 + 标 `needs_real_image`,**不手绘假物**。

### 4.4 SVG→PNG 渲染工具(共享)
- 新增 `skills/_shared/scripts/render-svg.js`(或 lib):Chrome headless 渲染 SVG→PNG(已手动验证 `--screenshot --window-size=1280,720` 可行)。探测 Chrome 路径,缺失则报错降级。
- 被 4.5 视觉审查 与 4.6 预览门共用。

### 4.5 review-core 视觉审查(review-core + gemini-cli)
- `review` 模式增加 **渲染步骤**:**资产页**(`asset.needed=true`)用 4.4 渲染 PNG → 调 `invoke-gemini-ppt.ts --image <png>`(`--image`/vision **管线已存在**,bible_review 在用)→ 让 Gemini **看图**评分。**数据页维持现有文本(SVG 源码)审查**,省 token/时延。
- **新增评分维度**:"资产贴切/专业度"(0-10)——配图是否真实贴合文案、有无假图标冒充实物、整体专业度。< 阈值 → critical,进 fix loop 或回搜图。
- suggestions JSON 加 `reason` 字段(为什么这图/版式不专业),可追溯。
- Gemini 不可用时:沿用现有降级(只硬规则,不伪造美学分);视觉维度同样跳过而非伪造。

### 4.6 人工预览门(commands/ppt.md 编排,workflow 层)
- Phase 6 **内部**、批量设计**之前**新增一道 **Hard Stop**:
  - slide-core 先只出**样片**(封面 + 1 张代表性资产页),用 4.4 渲染 PNG。
  - 一次性展示:**样片 PNG**(确认风格)+ **全部资产页候选配图 PNG**(确认配图对不对)+ **缺图清单**(`status:missing`)。
  - 用户操作:接受 / 替换某页图 / 丢官方图进 `images/` / 接受抽象处理。
  - 确认后 slide-core 才**批量**出其余页(避免 1h53m 全量白跑)。
- 与 `--stop-at` 协同:作为新的可观察停点(如 `--stop-at=preview`);`--run-id` 恢复后可续。
- 缺图退路天然由此门兜底,**不另设机制**。

## 6. 分阶段实现顺序(writing-plans 细化)

6. **视觉审查**:review-core 渲染 + `--image` 接线 + 资产维度 + reason。
7. **交付**:images 拷贝进 output。

## 8. 风险与缓解(诚实记录)

| 风险 | 缓解 |
|---|---|
| 自动搜图质量不稳/版权/水印 | 移出关键路径;人工门兜底 + 用户官方图;自用场景版权非阻塞 |

| 视觉审查 token/时延上升(渲染+传图) | 仅对资产页强制视觉审查;数据页可维持文本审查;复用单一渲染产物 |
| 里程碑偏大(碰 4 agent + 2 新工具) | 第 6 节分阶段;每阶段独立可测;机械自修已拆出 |
