## 1. 问题与目标

**动因(dogfood)**:5/12 失败页的原因高度集中在 slide-core 出图时的**确定性硬违规**(字号 <14、安全区顶破、暗底对比度),这些本可在生成阶段自修,却漏到 Gemini → 触发昂贵 fix loop。slide-core 现有"生成后校验"**只报不(可靠)修**(靠 Claude 肉眼手改)。

**目标**:把"只报"升级为"**确定性脚本自修**",在送 Gemini 前清掉机械硬违规。量化目标:首轮通过率 58%→≥85%、平均修复轮次 0.8→≤0.3。

**🔴 自审发现的关键约束(决定设计形态)**:真实 SVG 里**嵌套 `<g transform>` 内的元素用的是局部坐标**(实测 slide-06:`<text x="62" y="14">` 在一个平移后的卡片组内,完全合法)。因此**按原始坐标盲目钳位安全区会破坏布局**——这正是 dogfood "钳进安全区" 字面做法的陷阱。M2.6 必须只做**能保证"只会变好、绝不变坏"**的修复:
- 全局安全的修复(与 transform 无关)直接做:字号下限、颜色 token 替换。
- 坐标相关的修复**只针对顶层、且语义角色明确**的元素(主标题、页码),靠 slide-core 打的 `data-role` 标记 + "无 transform 祖先"双重保险来定位,绝不动嵌套元素。
- 任何无法确定性安全修复的违规,**保持现状交给已有的 Gemini fix loop**,而不是冒险乱改。

**非目标**:per-element 背景对比度计算(需解析 CTM + z-order,不确定性高);review-core 效率调优(node vs npx tsx、瘦身 prompt、Gemini 超时)——拆为可选的 M2.7。

## 2. 架构

新增纯函数库 `skills/_shared/scripts/lib/svg-autofix.js`(无 I/O,单元测试),slide-core 在"生成后校验"步骤调用它(把"只报"改成"先确定性自修,再校验剩余项报给 Gemini")。slide-core 同时给主标题/页码/小标签打 `data-role`,让坐标类修复可精确、安全地定位。

```
slide-core 生成 SVG
 → svg-autofix(确定性自修:字号下限 / 暗底 token 对比度 / 顶层 title|page-number 安全带钳位 / 明确出画布的元素夹回)
 → 既有 Post-Generation Validation(只报剩余的、不能确定性修的项)
 → 送 Gemini(只剩美学 + 真正模糊的问题)
```

## 3. 组件设计

### 3.1 `svg-autofix.js`(新,纯函数)
导出 `autofixSvg(svgString, opts) → { svg, fixes: [{type, detail}] }`。`opts` 含 `{ theme: "dark"|"light", tokens, fontFloor=14, labelFloor=12 }`。每类修复独立、可单独测试,且每类都满足"只会变好":

1. **字号下限(全局安全)**:把所有 `font-size` < `fontFloor` 抬到 `fontFloor`;`data-role="label"`/`"footnote"` 的元素用 `labelFloor`。字号是绝对值,与 transform 无关 → 安全。(M2 已基本满足,本项是安全网 + 抓住漏网。)
2. **文本对比度自修(全局安全,纯色彩数学)**:
   - **主题推断**(无需 YAML 加字段):取 `tokens.background` 计算 WCAG 相对亮度,< 0.5 → 暗主题,否则浅主题。(实测:无 `theme`/`accent_light` 字段,只能从 `background` 推。)
   - **参考背景**(规避嵌套/z-order 推断):用"最坏面"——暗主题取 `{background, card_bg}` 中**更暗**者,浅主题取**更亮**者。对该最坏面读得清,则任一表面都读得清,无需解析元素究竟落在哪层。
   - **修复**:仅对 **`<text>`/`<tspan>`** 元素,计算其 `fill` 对参考背景的对比;若低于阈值(大字 ≥3:1、`data-role=label`/小字 ≥4.5:1),则**沿亮度方向调整该 fill**(暗主题向白、浅主题向黑)到刚好达标。纯色彩数学、确定性、只提升可读性;不改装饰(`data-decorative`)、不改非文本。无需 `accent_light` 或手维护坏色表 → 既修掉 dogfood 的 `#6366f1`,也泛化到任何低对比文本。
3. **顶层 title / page-number 安全带钳位(角色定向,坐标安全)**:仅对**直接挂在根 `<svg>` 下、无 transform 祖先、且带 `data-role="title"` 或 `data-role="page-number"`** 的 `<text>`:
   - `title`:若基线 `y` < 92,抬到 92(标题上方无内容,下移安全)。
   - `page-number`:若基线 `y` > 688,提到 688;若 `x` > 1220 收到 1220(页脚区下方/右侧无内容,收回安全)。
   - 不满足"顶层 + 无 transform + 有 role"任一条件 → **跳过**(交给 Gemini)。绝不碰嵌套坐标。
4. **明确出画布夹回(坐标安全)**:仅当**顶层**元素的坐标明确落在画布外(`x<0`、`y<0`、`x>1280`、`y>720` 这种真正裁切)时,夹回硬边。嵌套元素一律不动。

每次修复记入 `fixes` 数组,便于日志/审计与测试断言。

### 3.2 slide-core 打语义角色 + 调用自修
- slide-core 生成时给:主标题 `data-role="title"`、页码 `data-role="page-number"`、小标签/脚注 `data-role="label"`。(已有 `data-decorative` 先例,加 `data-role` 同源。)
- 生成后**先调** `svg-autofix` 自修并写回 SVG,**再**跑既有 Post-Generation Validation(后者现在只会报"不能确定性修"的剩余项,数量大降)。
- CLI 包装 `skills/_shared/scripts/svg-autofix-cli.js <in.svg> [--theme dark] [--out <path>]`,供 slide-core 用 Bash 调用,无 Node 时散文降级(沿用项目惯例)。

### 3.3 (可选小增益)收紧 validator 安全区误报
既有 Post-Generation Validation 的 "y<40/x<60…" 是**按原始坐标扫描**,对嵌套元素会**误报**。把该检查改为只对"顶层无 transform 祖先"元素生效(与 3.1 同一安全判据),减少假阳性、少触发无谓 fix。属正确性改进,纳入本里程碑。

## 4. 测试策略
- `node:test`(`svg-autofix.js`):
  - 字号 <14 抬到 14;`data-role=label` 用 12;≥14 不动。
  - 主题推断:`background=#0f172a`→dark、浅色 background→light。
  - 暗主题下低对比 text fill(如 `#6366f1` on `#0f172a`)被调亮到 ≥3:1;`data-decorative` 元素与非文本不动;已达标的 fill 字节不变。
  - 色彩数学单测:`luminance`/`contrastRatio` 已知值断言(如黑白 21:1)。
  - 顶层 `data-role=title` y=70 → 92;嵌套(有 transform 祖先)的同名元素**不动**(防回归核心)。
  - 顶层 page-number y=700 → 688。
  - 明确出画布顶层元素夹回;嵌套不动。
  - 每类返回正确 `fixes` 记录;无违规时 `fixes` 为空、SVG 字节不变。
- grep 结构测试(`ppt-m2.6-prose.test.js`):slide-core.md 含 `data-role="title"|"page-number"`、含调用 `svg-autofix`(生成后先自修再校验);validator 安全区检查限定顶层的说明。
- 集成烟测:对真实 `slides/*.svg` 跑 CLI,确认不破坏(渲染前后 xmllint 通过、嵌套坐标无改动)。

## 5. 实现顺序
1. `svg-autofix.js` 字号下限(最简、最安全)+ 测试
2. 暗底 token 对比度替换 + 测试
3. 顶层 role 定向安全带钳位 + 出画布夹回 + 测试(含"嵌套不动"回归)
4. CLI 包装 + 集成烟测
5. slide-core 散文:打 `data-role` + 接 `svg-autofix`(生成后先修再校验)
6. validator 安全区检查收紧到顶层
7. 全量回归 + 路线图回填(M2.6 ✅,P3 下一个)

## 6. 风险与缓解
| 风险 | 缓解 |
|---|---|
| 盲目坐标钳位破坏嵌套布局 | 核心设计原则:坐标类修复只碰"顶层+无 transform+有 role";其余交 Gemini |
| 字号抬升导致溢出 | 只抬明确违规(<14);溢出极少且由 Gemini 审查兜底 |
| token 替换误伤装饰 | 只换暗主题下的 **text** fill + 已知坏色表;装饰(data-decorative)不动 |
| slide-core 漏打 role | 角色缺失 → 对应坐标修复安全跳过(降级不报错) |
| autofix 改坏 SVG | 每步后 xmllint;CLI 失败保留原 SVG |
